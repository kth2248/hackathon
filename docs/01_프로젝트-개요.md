# 1. 프로젝트 개요 — 왜 이렇게 만들었나

## 목표가 변해온 과정
이 프로젝트는 준비 과정에서 목표가 세 번 바뀌었고, 그때마다 전략도 진화했습니다.

1. **처음** — "무한한 상상, 무해한 AI" 주제의 VPython 해커톤. 아이디어 몇 개를 만드는 게 목표.
2. **중간** — 실제 대회 주제가 **SDGs(지속가능발전목표)**로 공개. 데이터 분석·시뮬레이션·로봇으로 지속가능한 미래의 해결책을 탐구.
3. **지금** — 순위를 다투는 대회가 아니라 **학생의 역량을 관찰해 생기부를 써주는** 성격일 가능성 + **게임 프로그래머 진로** 어필 + "어떤 SDG가 갑자기 지정될지 모름".

이 변화 때문에 전략이 **"완성작 하나를 잘 만들기" → "무엇이 나와도 대응할 수 있게 준비하기"**로 바뀌었습니다.

## 프로젝트를 관통한 3가지 원칙

### ① 완제품이 아니라 "부품"으로 만든다
대회 규정과 최종 주제가 불확실했습니다. 특정 아이디어에 묶인 완성품은 주제가 바뀌면 버려야 합니다. 그래서 **어떤 아이디어에도 재사용되는 부품**(벡터 계산, 3D 객체 생성, 슬라이더 UI, 경로탐색, 최적화 등)을 먼저 쌓았습니다. → 당일에는 필요한 부품만 골라 "레고 조립".

### ② 오프라인에서 100% 동작해야 한다
대회장 인터넷을 신뢰할 수 없다는 가정. 인터넷이 필요한 기능(예: 자연어를 3D로 바꾸는 Claude API)은 **인터넷 없이 도는 규칙기반 버전**을 기본으로 두고, API 연동은 "되면 보너스"로만 설계했습니다.

### ③ "슬라이더를 움직이면 결과가 즉시 변하는 것"이 승부처
심사위원과 생기부 평가자가 기억하는 건 화려한 코드가 아니라 **조작하니 눈앞의 결과가 달라지는 순간**입니다. 그래서 모든 데모에 실시간 슬라이더 + 결과 그래프를 통일해 넣어, "변수를 바꿔 실험 → 정량 비교"가 자연스럽게 나오도록 했습니다.

## 이 프로젝트의 진짜 결과물
완성된 데모 수십 개 자체가 아니라, **무엇이 나와도 흔들리지 않는 "준비된 상태"**입니다.
부품을 쌓고 → 온갖 경우를 미리 데모로 만들어 보고 → 즉석 조립용 뼈대를 굳히고 → 진로(게임)와 생기부(탐구 과정)까지 연결한 것이 핵심입니다.
