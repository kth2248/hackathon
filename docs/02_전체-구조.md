# 2. 전체 구조 — 무엇이 어디에 있나

프로젝트는 딱 두 갈래로 나뉩니다: **함수는 부품(`parts`), 실행되는 것은 완성품(`products`).**

```
프로젝트/
├── parts/         🧩 재사용 함수 = 기능 종류별 폴더
│   ├── vectors/       벡터 수학(방향·거리·회피)
│   ├── scene/         3D 씬·객체·격자 렌더
│   ├── ui/            슬라이더·토글
│   ├── pathfinding/   A* 경로탐색(게임 길찾기)
│   ├── world/         격자 맵·장애물
│   ├── steering/      이동·군집·도주·추격
│   ├── optimization/  유전알고리즘·자원배분
│   ├── nlp/           자연어 명령 파서
│   ├── models/        전염병(SIR)·저수지 모델
│   ├── risk/          위험도 계산
│   ├── generation/    절차적 배치(줄·나선·원·격자)
│   ├── dataviz/       실시간 그래프
│   ├── input/         키보드 입력(게임 조작)
│   ├── gameai/        유한상태기계(FSM)
│   └── tests/         자동 테스트 49개
│
├── products/      🚀 실행되는 완성 데모 (python으로 바로 실행)
│   ├── SDG01~17 (1차)   각 SDG의 3D 에이전트 시뮬
│   ├── SDG01~17 (2차)   같은 SDG를 다른 장르로
│   ├── A/B/D/E/F/통합안   "무해한 AI" 초기 프로토타입
│   ├── TEMPLATE_sdg_base  즉석 조립용 공용 뼈대
│   └── GAME_ocean_cleanup 플레이 가능한 게임
│
└── docs/          📄 이 보고서
```

## 두 개의 저장소로 분리한 이유
- **라이브러리 저장소(`hackathon_import`)** — `parts` 부품만. 다음 대회·프로젝트에서도 재사용하는 자산.
- **해커톤 저장소(`hackathon`)** — 이번 대회 완성품 + 부품 사본. clone만 하면 오프라인에서 바로 실행.

→ "계속 쓸 재사용 자산"과 "이번 대회 결과물"을 구분해 각각 깔끔하게 관리·공유하기 위함.

## 실행 방법 (참고)
- 설치: `pip install -r requirements.txt` (vpython, pytest)
- 실행: 각 완성품 폴더에서 `python main.py` → 브라우저 창에 3D 화면이 뜸
- 검증: `pytest parts/tests/` → 순수 계산 부품 49개 자동 통과 (인터넷·화면 불필요)
