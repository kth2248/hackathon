# PROJECT_GUIDE.md — 이 킷이 무엇이고, 왜 이렇게 만들었는가

이 문서는 "각 파일이 무엇인지 / 왜 지금 이것만 만들었는지 / 당일 어떻게 쓰는지"를
초보자 눈높이로 풀어 쓴 **설명서**입니다. 코드를 처음 보는 사람이 이 문서만 읽어도
전체 그림을 이해할 수 있게 쓰였습니다.

---

## 1. 한 문장 요약

> **"대회 당일 어떤 아이디어로 가든 재사용되는 순수 부품만 미리 만들어 둔 도구 상자."**

시뮬레이션은 결국 세 가지 일을 반복합니다:
1. **계산한다** (어디로 갈지, 얼마나 가까운지) → `vector_helpers.py`
2. **화면에 그린다** (구슬, 장애물, 바닥) → `vpython_utils.py`
3. **사람이 조작한다** (슬라이더, 스위치) → `ui_widgets.py`

이 세 가지는 아이디어가 A안이든 B안이든 C안이든 **똑같이 필요**합니다.
그래서 아이디어에 종속되지 않는 이 부품들만 먼저 완성했습니다.

---

## 2. 왜 "완성품"이 아니라 "부품 상자"인가?

핵심 이유는 **대회 규정이 아직 미확인**이기 때문입니다.

- 사전 제작물(미리 만든 코드)을 어디까지 허용하는지 모릅니다.
- 만약 "완성된 프로젝트"를 미리 만들어 갔다가 규정 위반이면 전부 버려야 합니다.
- 하지만 `direction_to()` 같은 **범용 수학 함수**는 누가 봐도 "그냥 라이브러리"이므로
  대부분의 규정에서 안전하고, 규정 확정 후에도 그대로 재사용됩니다.

> 비유: 요리 대회 전에 "완성된 요리"를 만들어 가면 반칙일 수 있지만,
> **칼을 갈아두고 재료를 손질해 두는 것**은 안전합니다. 이 킷은 후자입니다.

`main_template.py`(실제 요리 = 완성 로직)는 그래서 **보류 상태**로 두었습니다.
규정과 아이디어가 확정되는 순간, 이 부품들을 조립만 하면 됩니다.

## 3. 파일별 상세 설명

### 3-1. `vector_helpers.py` — "계산 담당" (두뇌)
VPython 화면 없이도 돌아가는 **순수 수학 함수**들입니다.
- `direction_to(A, B)`: A에서 B로 가는 방향(길이 1의 화살표). "목표를 향해 간다"의 핵심.
- `distance(A, B)`: 두 점이 얼마나 떨어졌나. "충돌/회피 판단"의 기준.
- `avoid_vector(...)`: 장애물이 너무 가까우면 "반대로 피하는 방향"을 돌려줌. **A안(무해한 AI)의 심장.**
- `clamp_speed(...)`: 너무 빨라지지 않게 속도 제한. 시뮬레이션이 폭주하지 않게 함.
- `blend_vectors(v1, v2, weight)`: "가고 싶은 방향"과 "피해야 하는 방향"을 섞음.
  → "목표로 가되 사람은 피한다"는 **무해한 AI의 행동을 한 줄로** 표현.

왜 순수 함수인가? → 화면 렌더링과 분리돼 있어서 **`pytest`로 정확성을 자동 검증**할 수 있습니다.
(`test_vector_helpers.py`가 이 역할)

### 3-2. `vpython_utils.py` — "그리기 담당" (손)
매번 반복되는 3D 객체 생성 코드를 함수로 묶었습니다.
- `make_scene()`: 3D 창(캔버스) 하나 생성.
- `make_agent()`: 움직이는 주인공 구슬 (경로 흔적 옵션 O).
- `make_obstacle()`: 피해야 할 장애물 구슬. A안에선 '사람', C안에선 '다른 개체'.
- `make_floor()`: 바닥. 공간감이 필요할 때만 선택 사용.
- `make_multiple_agents()`: 여러 개체 한 번에 배치 (C안 군집 대비, 우선순위 낮음).

"이 구슬이 무슨 의미인지"는 여기서 정하지 않습니다. **의미 부여는 조립 단계(main_template)에서.**

### 3-3. `ui_widgets.py` — "조작 담당" (리모컨)
발표에서 심사위원의 눈길을 끄는 건 **"실시간으로 값을 바꾸니 결과가 즉시 변하는 것"**입니다.
- `make_labeled_slider(...)`: 슬라이더 + "현재 값 XX" 라벨을 한 세트로. 값이 바뀌면 라벨도 자동 갱신.
- `make_toggle(...)`: 체크박스 + 상태 라벨. **A안의 "무해한 AI ON/OFF 스위치"**에 그대로 사용.

### 3-4. `test_vector_helpers.py` — "품질 검사" (자동 채점기)
`vector_helpers`의 각 함수가 정확한 값을 내는지 자동으로 검증합니다.
`pytest test_vector_helpers.py -v`로 실행. 초록불이면 계산 로직은 믿고 써도 됩니다.

### 3-5. `demo_ui_widgets.py` — "UI 리허설"
슬라이더와 토글이 **브라우저에서 실제로 조작되는지** 눈으로 보는 데모.
구슬 크기를 슬라이더로 바꾸고, 체크박스로 숨겼다 보였다 해봅니다.

### 3-6. `offline_test.py` — "가장 중요한 안전 점검" ⭐
**대회 전날 Wi-Fi를 끄고 반드시 실행**하세요. 세 가지를 확인합니다:
1. 내가 만든 부품들이 잘 import 되는가
2. VPython이 인터넷 없이 브라우저 창을 띄우는가 (← **여기가 핵심**)
3. 애니메이션 루프(`rate()`)가 정상 도는가

VPython은 브라우저로 3D를 그리기 때문에, 대회장 네트워크가 불안정하면 문제가 생길 수 있습니다.
그래서 **미리 오프라인에서 되는지 확인**하는 것이 이 킷에서 제일 중요한 작업입니다.
❌가 하나라도 나오면 `fallback_matplotlib.py`(백업 플랜)를 준비합니다.

### 3-7. `main_template.py` — "조립 설계도" (⏸️ 보류)
위 부품들을 조립해 실제 A안 시뮬레이션을 만드는 자리입니다.
**지금은 실행하지 않습니다.** 문법/import만 맞으면 됩니다.
규정과 아이디어가 확정되면 `run()` 안의 로직을 다듬고 맨 아래 주석을 해제합니다.
